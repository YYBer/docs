The Fibe WebSocket API delivers real-time market data and order status events with sub-second latency, eliminating the need to poll REST endpoints for time-sensitive information. You can subscribe to live orderbook snapshots, individual trade events, mid-price ticks across all markets, OHLCV candle updates, and per-user order status changes — all over a single persistent connection. The Fibe TypeScript SDK manages the connection lifecycle for you, but you can also connect with any standard WebSocket client.

## Connection URLs

Connect to the Fibe WebSocket endpoint at the URL for your target network:

| Network | URL |
|---------|-----|
| Mainnet | `wss://api.fibe.com/ws` |
| Testnet | `wss://api.fibe-testnet.com/ws` |

### SDK Connection (Recommended)

Use `api.WebSocketSubscriptions.create` to establish a managed connection. The SDK handles ping/pong keepalives, automatic reconnection, and subscription restoration after a disconnect.

```typescript
import { api } from '@fibe/sdk';

const subscriptions = await api.WebSocketSubscriptions.create(
  'wss://api.fibe.com/ws',
  (error) => console.error('WebSocket error:', error)
);
```

### Raw WebSocket Connection

If you prefer to manage the connection yourself, connect with any standard WebSocket client:

```typescript
const ws = new WebSocket('wss://api.fibe.com/ws');

ws.onopen = () => {
  console.log('Connected to Fibe WebSocket');
};

ws.onmessage = (event) => {
  const message = JSON.parse(event.data);
  console.log('Received:', message);
};

ws.onerror = (error) => {
  console.error('WebSocket error:', error);
};

ws.onclose = () => {
  console.log('Disconnected from Fibe WebSocket');
};
```

## Subscription Channels

### `l2Book` — Real-Time Orderbook

Receive incremental orderbook snapshots aggregated at a given price step. Each message contains the full current state of the top-of-book.

<Tabs>
  <Tab title="SDK">
    ```typescript
    const subscription = subscriptions.subscribeToL2Book(
      0,      // marketIndex
      0.01,   // priceStep
      (data) => {
        console.log('Best bid:', data.bids[0]);
        console.log('Best ask:', data.asks[0]);
      }
    );

    // Stop receiving updates
    subscription.unsubscribe();
    ```
  </Tab>
  <Tab title="Raw WebSocket">
    ```typescript
    // Subscribe
    ws.send(JSON.stringify({
      method: 'subscribe',
      subscription: {
        type: 'l2Book',
        market: 0,
        ps: 1000000  // scaled price step
      }
    }));

    // Unsubscribe
    ws.send(JSON.stringify({
      method: 'unsubscribe',
      subscription: {
        type: 'l2Book',
        market: 0,
        ps: 1000000
      }
    }));
    ```
  </Tab>
  <Tab title="Message Format">
    ```json
    {
      "channel": "l2Book",
      "data": {
        "market": 0,
        "ps": 1000000,
        "bids": [
          { "px": "103.44", "sz": "125.5" },
          { "px": "103.43", "sz": "250.0" }
        ],
        "asks": [
          { "px": "103.46", "sz": "100.0" },
          { "px": "103.47", "sz": "200.0" }
        ]
      }
    }
    ```
  </Tab>
</Tabs>

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `marketIndex` | number | Numeric market identifier |
| `priceStep` | number | Price aggregation granularity (e.g. `0.01`) |

### `trades` — Real-Time Trade Events

Receive a notification each time a trade is executed on a market. Each message delivers an array of one or more trades.

<Tabs>

          console.log(`${direction} ${trade.sz} @ ${trade.px}`);

  </Tab>

## Connection Management

### Ping / Pong

The SDK automatically sends a ping every 15 seconds and validates the pong response to keep the connection alive. If you use a raw WebSocket connection, implement your own keepalive:

```typescript
// Send a ping every 15 seconds
setInterval(() => {
  if (ws.readyState === WebSocket.OPEN) {
    ws.send(JSON.stringify({ method: 'ping' }));
  }
}, 15000);

// Confirm the connection is alive by handling the pong
ws.onmessage = (event) => {
  const message = JSON.parse(event.data);
  if (message.channel === 'pong') {
    // Connection is healthy
  }
};
```

### Auto-Reconnection (SDK)

When you use the SDK, disconnections trigger an automatic reconnection with exponential backoff:

| Setting | Value |
|---------|-------|
| Initial retry delay | 1 second |
| Maximum retry delay | 30 seconds |
| Maximum attempts | 5 |

All active subscriptions are automatically restored once the connection is re-established.

### Manual Reconnection (Raw WebSocket)

If you manage your own WebSocket connection, implement reconnection logic in the `onclose` handler and resubscribe to all channels on reconnect:

```typescript
function connect() {
  const ws = new WebSocket('wss://api.fibe.com/ws');

  ws.onopen = () => {
    console.log('Connected — subscribing to channels');

    // Resubscribe to all required channels
    ws.send(JSON.stringify({
      method: 'subscribe',
      subscription: { type: 'allMids' }
    }));
  };

  ws.onclose = () => {
    console.log('Disconnected — attempting reconnect in 5s');
    setTimeout(connect, 5000);
  };
}

connect();
```

For more sophisticated retry logic, use exponential backoff to avoid overwhelming the server:

```typescript
let reconnectAttempt = 0;

function getReconnectDelay(): number {
  const delay = Math.min(1000 * Math.pow(2, reconnectAttempt), 30000);
  reconnectAttempt++;
  return delay;
}

function onConnectedSuccessfully(): void {
  reconnectAttempt = 0; // Reset counter on successful connection
}
```

## Rate Limits

| Resource | Limit |
|----------|-------|
| WebSocket connections | 100 per IP |
| Active subscriptions | 1,000 per IP |
| Messages sent to server | 2,000 per minute (across all connections) |
| User-specific subscriptions | 10 unique wallet addresses |

## Best Practices

Keep these guidelines in mind when building applications on top of the Fibe WebSocket API:

<CardGroup cols={2}>
  <Card title="Subscribe selectively" icon="filter">
    Only subscribe to the channels you actively consume. Each subscription uses server-side resources and counts against your IP's subscription limit.
  </Card>
  <Card title="Handle disconnections gracefully" icon="plug-circle-xmark">
    Use the SDK's built-in reconnection, or implement your own with exponential backoff. Never assume a WebSocket connection is permanently stable.
  </Card>
  <Card title="Process messages asynchronously" icon="bolt">
    Offload heavy computation (charting, aggregation, strategy evaluation) to worker threads or async queues. Blocking the message handler introduces latency.
  </Card>
  <Card title="Validate message data" icon="shield-check">
    Always confirm the expected fields are present in each message before accessing them. Defensive parsing prevents runtime errors from unexpected schema changes.
  </Card>
  <Card title="Use the SDK" icon="cube">
    The TypeScript SDK handles reconnection, ping/pong heartbeats, and subscription state management automatically — reducing the code you need to maintain.
  </Card>
  <Card title="Exponential backoff" icon="arrow-up-right-dots">
    When reconnecting manually, back off exponentially from 1 s up to 30 s before retrying. Immediate reconnect loops can trigger rate limiting.
  </Card>
</CardGroup>

## End-to-End Example

The following example opens three simultaneous subscriptions — orderbook, trades, and all-mids — runs for 60 seconds, then cleanly unsubscribes from each:

```typescript
import { api } from '@fibe/sdk';

async function main() {
  // Establish a managed WebSocket connection
  const subscriptions = await api.WebSocketSubscriptions.create(
    'wss://api.fibe.com/ws',
    (error) => console.error('WebSocket error:', error)
  );

  let bestBid = '0';
  let bestAsk = '0';

  // Stream the SOL/USDC orderbook
  const orderbookSub = subscriptions.subscribeToL2Book(0, 0.01, (data) => {
    if (data.bids.length > 0) bestBid = data.bids[0].px;
    if (data.asks.length > 0) bestAsk = data.asks[0].px;

    const spread = parseFloat(bestAsk) - parseFloat(bestBid);
    console.log(`Bid: ${bestBid} | Ask: ${bestAsk} | Spread: ${spread.toFixed(4)}`);
  });

  // Stream individual trades
  const tradesSub = subscriptions.subscribeToTrades(0, (trades) => {
    trades.forEach(trade => {
      const side = trade.side === 'B' ? 'BUY ' : 'SELL';
      console.log(`[TRADE] ${side} ${trade.sz} @ ${trade.px}`);
    });
  });

  // Stream mid prices for all markets
  const midsSub = subscriptions.subscribeToAllMids((mids) => {
    console.log('[MIDS] SOL-USDC:', mids['0']);
  });

  // Run for 60 seconds, then clean up
  setTimeout(() => {
    console.log('Unsubscribing from all channels...');
    orderbookSub.unsubscribe();
    tradesSub.unsubscribe();
    midsSub.unsubscribe();
    console.log('Done.');
  }, 60000);
}

main().catch(console.error);
```
